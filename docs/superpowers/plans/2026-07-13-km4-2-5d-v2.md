# KM4/F151 Repair-Grade 2.5D V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the KM4/F151 debug geometry view into a source-honest, repair-grade orthographic 2.5D board model.

**Architecture:** A pure model-profile module converts compiled component records into conservative render descriptors. `BoardRenderer` consumes those descriptors to build a layered Three.js scene with a clipped engineering surface, flat uncertainty overlays, procedural package meshes, and stable camera controls. Existing registration and evidence modules remain the source of selection state.

**Tech Stack:** JavaScript ES modules, Three.js, HTML/CSS, Node test runner, Python validation, Playwright/browser QA.
