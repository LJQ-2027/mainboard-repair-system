# 资料入库到前端应用工作流

本项目收到新的制造中心、技术支持或海外现场资料后，不应只做文件保存。每次资料入库都必须完成“保存、结构化、前端应用、SOP 转译判断”四步。

## 1. 保存原始资料

- 原始文件保存到 `source-materials/`。
- 如果是压缩包，同时保留 `_raw/` 原始包和 `packages/` 解包后的短目录结构。
- 文件路径过长时，按机型或项目代号整理短目录，但不删除原始压缩包。

## 2. 更新结构化知识库

必须更新：

- `knowledge-base/source-records.json`
- `knowledge-base/model-board-assets.json`

按资料内容选择更新：

- `knowledge-base/sop-drafts.json`
- `knowledge-base/interactive-sop-prototypes.json`
- `knowledge-base/fault-packages.json`
- `knowledge-base/gap-requests.json`
- `knowledge-base/mtk-signal-reference.json`

## 3. 同步前端可见状态

如果资料能补齐机型卡片字段，前端必须同步显示，不允许仍显示“待补”。

当前机型资料卡片字段口径：

- 维修指导书
- 主板原理图
- 主板位号图
- 副板原理图
- 副板位号图
- 对照表
- 主板实物照片

资料入库后，需要确认：

- 卡片统计数字更新。
- 卡片字段状态更新。
- 查看详情能看到文件清单和打开入口。
- 诊断工作台能聚合到相关机型、故障包或 SOP。

## 4. 判断是否可转译 SOP

当某个机型至少具备以下资料时，应主动尝试生成维修步骤指导：

- 维修指导书
- 主板原理图
- 主板位号图

如果还具备副板资料、对照表、平台信号参考，则应纳入步骤指导。

维修步骤指导不要求等待人工录入真实案例。第一版可以基于现有工程资料设计，字段包括：

- 适用机型
- 适用故障
- 准备工具
- 前置检查
- 操作步骤
- 判断条件
- 测试点与参考值
- 图纸/位号图入口
- 修后验证标准
- 待复核问题

## 5. 当前阶段不强制维修边界

当前阶段不把维修边界作为 SOP 生成的前置条件。边界判断容易模糊，先通过步骤指导和修后验证提升可执行性。

## 6. 必须验证

凡是资料状态或 SOP 展示改动，都需要做 P3 前端真实路径验证：

- 页面能打开。
- 相关卡片状态正确。
- SOP 页面能看到步骤和参考值。
- 交互式 SOP 能切换和点击。
- 桌面和移动视口无明显横向溢出。
- 控制台无运行时报错。
