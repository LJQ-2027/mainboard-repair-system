# 第一阶段知识库填充计划

## 1. 当前阶段目标

第一阶段不是把所有资料一次性填满，而是先跑通一条可靠链路：

```text
文件资料
-> 自动识别和归类
-> 抽取结构化字段
-> 形成知识条目
-> 进入对应知识库
-> 在系统中可查询、可复用
-> 现场案例继续回流
```

阶段目标可以概括为：

- 建立资料入库流程；
- 建立第一批样板知识；
- 建立缺口清单；
- 为后续机型详情页、故障知识页、SOP 页面和案例回流功能提供真实内容。

## 2. 第一批优先范围

第一批建议不要超过以下范围：

| 范围 | 建议数量 |
|---|---|
| 重点机型 | 2-3 个 |
| 高频故障 | 3-5 类 |
| 真实维修案例 | 每类故障 3-5 条 |
| 培训资料 | 1-3 份 |
| SOP 草案 | 3-5 条 |
| 点位/器件样板 | 每个机型先补关键模块 |

优先选择：

1. 土耳其 / EE1 当前高频 L4 主板故障；
2. 中方技术人员反复处理过、经验比较成熟的问题；
3. 换板成本高但可能维修的问题；
4. 已经有培训资料或维修指导书支撑的问题。

## 3. 资料收集优先级

### P0：最应该先找

- L4 培训资料；
- 主板维修培训标准；
- 器件维修培训；
- 高频故障维修案例；
- 中方技术人员经验总结；
- 常见故障排查流程；
- 维修指导书。

### P1：有就马上纳入

- 点位图；
- 位号图；
- BOM；
- 关键测试点清单；
- 工具清单；
- 修后验证标准；
- Log 分析案例。

### P2：后续再系统化

- 原始原理图；
- 完整 BoardView / Layout；
- 详细 FA 报告；
- 工艺参数；
- 自动检测治具相关资料。

## 4. 入库流程

### Step 1：文件登记

使用 [资料入库登记模板](./source-ingestion-template.md) 记录：

- 文件名；
- 文件类型；
- 来源；
- 主分类；
- 可拆分进入的知识库；
- 关联机型；
- 关联故障；
- 可抽取字段；
- 缺失字段；
- 下一步处理建议。

### Step 2：内容拆解

把文件拆成结构化知识：

- 机型资料；
- 故障知识；
- 器件与点位；
- SOP 步骤；
- 维修案例；
- 维修边界；
- 培训条目；
- 缺口需求。

### Step 3：样板入库

第一阶段先不做复杂后台。可以先用 Markdown 或 JSON 建样板数据，确认结构后再接入系统页面。

建议先形成：

- 1 个机型详情样板；
- 1 个故障详情样板；
- 1 条 SOP 样板；
- 3 条维修案例样板；
- 1 张缺口清单样板。

### Step 4：页面承接

样板数据确认后，逐步进入产品页面：

- 工作台首页展示资料状态和缺口；
- 机型资料库展示机型详情；
- 故障知识库展示故障详情；
- 案例沉淀展示真实案例；
- AI 辅助读取结构化知识作为上下文。

## 5. 第一批知识条目建议

### 机型维度

优先从当前 demo 已有数据中选：

- `X6878`：已有较多资料链接和器件位号；
- `X6840` / `X6887` / `KO5`：已有部分资料链接；
- 土耳其 / EE1 实际高频机型：如与 demo 不一致，以现场优先。

### 故障维度

优先选择：

- 不开机；
- 充电异常；
- 无服务 / 射频异常；
- 下载无端口；
- 死机重启；
- 显示异常。

### 案例维度

优先收集以下类型：

- 中方技术人员已经修复过的典型案例；
- 海外本地维修员处理失败后交给中方技术人员的案例；
- 直接换板但可能存在维修机会的案例；
- 高频重复发生的问题；
- 可以转成培训或 SOP 的案例。

## 6. 第一阶段完成标准

第一阶段样板填充完成，应至少产出：

- 2-3 个机型资料条目；
- 3-5 类故障知识条目；
- 10-20 条真实维修案例；
- 3-5 条 SOP 草案；
- 1 份工具与能力边界清单；
- 1 份资料缺口清单；
- 1 套文件入库登记记录。

更重要的是跑通流程：

```text
资料进来后，能被识别、归类、拆字段、形成条目，并最终被系统页面或 AI 辅助能力使用。
```

## 7. 后续产品开发衔接

知识填充完成第一批样板后，建议产品侧按以下顺序开发：

1. 机型资料库页面；
2. 故障知识库页面；
3. 维修案例库页面；
4. 缺口与需求清单页面；
5. SOP 详情页；
6. AI 辅助读取结构化知识的上下文能力。

这样系统会从“demo 数据驱动”逐步变成“售后真实知识库驱动”。
