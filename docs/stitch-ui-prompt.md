# Stitch UI Prompt: 海外主板维修知识工作台

请为“海外主板维修能力建设项目”设计一套 Web 系统 UI。

这是一个面向海外本地维修员、中方技术人员、售后技术支持的主板维修知识工作台，不是营销页，不是 AI 炫技平台，也不是纯项目汇报页。系统的第一性是实用：帮助用户快速查找机型资料、故障知识、器件点位、维修培训、历史案例和标准流程，把零散经验沉淀成可查、可读、可复用的维修知识库。

## 产品定位

- 主体是知识库型维修工作台。
- AI 和软硬件自动化检测是长期愿景，但不是当前界面的视觉主体。
- 当前阶段重点是资料沉淀、检索、培训、案例复用和制造中心协作。
- 页面要适合真实办公和维修场景，给人稳定、专业、可信赖的感觉。

## 核心用户

- 海外本地维修员：需要简单、清晰、能按资料执行。
- 中方技术人员：需要沉淀经验、查案例、补充资料。
- 售后技术支持 / L4 技术员：需要高效检索、判断故障、组织培训。
- 制造中心工程师：需要看清哪些资料需要协作补充。

## 整体风格

- 浅色知识库 + 工程系统风格。
- 中等信息密度。
- 清晰、克制、稳定、实用。
- 不要大面积深色控制台。
- 不要营销页式 Hero。
- 不要 AI 紫蓝渐变、霓虹光效、玻璃拟态、过度圆角。
- 不要 emoji 作为功能图标。
- 不要让页面显得像 demo 或玩具。

## 信息架构

采用左侧侧边栏导航的多页面系统。导航包含：

1. 工作台首页
2. 机型资料库
3. 故障知识库
4. 器件与点位
5. 维修培训
6. 案例沉淀
7. AI 辅助
8. 能力路线图 / 项目规划

AI 辅助和能力路线图可以出现在导航中，但不要压过知识库主体。当前产品首先是维修资料和经验沉淀工作台。

## 第一轮优先设计页面

请先设计 3 个关键页面，不要一次性生成完整系统。

### 页面一：工作台首页

- 顶部提供强全局搜索，支持搜索机型、故障现象、器件位号、培训资料、历史案例、日志关键词。
- 提供“按机型进入”和“按故障现象进入”的快捷入口。
- 展示最近更新资料、常用培训资料、待制造中心补充资料。
- 轻量展示能力建设路线图，但不要喧宾夺主。
- 首页应该像一个工作入口，而不是项目宣传页。

### 页面二：机型资料详情页

- 展示某个机型的主板资料、培训文档、器件信息、常见故障、维修边界、历史案例。
- 内容要结构化，适合快速扫描。
- 可以使用标签、表格、分栏、状态标识。
- 右侧可以有轻量辅助面板，显示资料完整度、待补充项、AI 摘要入口、更新时间、协作方。
- 不要把所有内容做成大卡片堆叠。

### 页面三：AI 辅助页

- AI 是辅助工具，不是最终维修专家。
- 展示资料总结、案例匹配、日志解读、下一步排查建议。
- AI 输出必须体现来源、适用条件、人工确认。
- 文案避免夸张，不要写“自动修复”“一键诊断所有问题”。
- 视觉上要专业、克制，像工程辅助面板，而不是聊天机器人玩具。

## 能力路线图表达

可以在首页或独立页面中展示长期演进方向：

资料沉淀 → 结构化知识库 → 可视化点位 → 交互式 SOP → AI 辅助检索与案例匹配 → 轻量硬件检测工具 → AI + 软硬件自动化检测封装

请明确区分：

- 当前可用
- 建设中
- 规划中
- 需要制造中心协作

避免误导用户以为所有能力已经实现。

## 文案语气

- 工程系统语气为主，简洁、准确、可执行。
- 使用“机型资料库”“故障知识库”“器件与点位”“维修培训”“案例沉淀”“资料来源”“维修边界”“待补充资料”等明确词汇。
- 首页可以有一句项目目标，但不要堆口号。
- 避免“智能赋能”“未来科技”“效率革命”等泛化营销词。

## 视觉要求

- 使用专业的浅色背景。
- 使用低饱和强调色，最多一个主强调色。
- 表格、列表、标签和分栏要清晰。
- 卡片只用于承载独立信息，不要到处堆大卡片。
- 图标使用简洁线性图标，不使用 emoji。
- 字体适合中文办公系统，清晰易读。
- 页面要有真实工作系统的完成度，包括空状态、加载状态、资料来源、状态标签、更新时间、负责人或协作方信息。
